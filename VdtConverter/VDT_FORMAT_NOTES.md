# VDT フォーマット メモ（SiV.X 0.97a の実装から確認）

付属の仕様書（1993/10/05）と、SiV.X（"SiV Version 0.97a'93/04/19 Mon."、"Idea & Programming Tatsuya Ono."）を逆アセンブルして照らし合わせた結果。
アドレスは SiV.X のテキストセクション先頭からのオフセット。

## 仕様書と実装が違っていたところ

### ADPCM Rate の値は 0 / 2 / 4（仕様書の「0 と 3 と 4」は誤記）

`$325a` の「1 フレームあたりの音声サイズを決める」処理:

```
move.l  $20744.l, d0      ; ADPCM Rate
cmp 2 → d3 = $0F3C (3900)   ; 7.8kHz
cmp 4 → d3 = $1E78 (7800)   ; 15.6kHz
cmp 0 → d3 = 0              ; 無音
```

IOCS _ADPCMOUT のサンプリング指定（0=3.9k, 1=5.2k, 2=7.8k, 3=10.4k, 4=15.6k）と同じ番号。
`$1374` では `(Rate << 8) | パン` を作ってそのまま IOCS に渡している。
画面上の「音質 0〜2」は、ファイル上ではそれぞれ 0 / 2 / 4 になる。

### 無圧縮のフレームには Flame Len が無い

セーブ処理（`$60f2`〜）では、色質 0 のときフレームごとに「画像 30720 バイト＋音声」を続けて 1 回で書いている（`$6446`）。
Flame Len（4 バイト）を書くのは圧縮時だけ。これは仕様書の図（無圧縮の例）と一致していて、表の方の説明が圧縮時の形。

## 1 フレームあたりの音声バイト数

```
v = (1 秒のバイト数) ÷ (60 ÷ TimeScale)   ; どちらも整数除算
if (v が奇数) v++
```

| TimeScale | fps | 7.8kHz | 15.6kHz |
|---|---|---|---|
| 2 | 30 | 130 | 260 |
| 3 | 20 | 196 | 390 |
| 4 | 15 | 260 | 520 |
| 5 | 12 | 326 | 650 |
| 6 | 10 | 390 | 780 |
| 10 | 6 | 650 | 1300 |
| 12 | 5 | 780 | 1560 |
| 15 | 4 | 976 | 1950 |
| 20 | 3 | 1300 | 2600 |
| 30 | 2 | 1950 | 3900 |
| 60 | 1 | 3900 | 7800 |

ポスター用の音声も同じサイズ。

## ファイルの並び（無圧縮）

```
"SiV"                       3 バイト
コメント … $0A              SiV 本体は " Version 0.97a'93/04/19 Mon." を書く。読み込み時は $0A まで読み飛ばすだけ
Poster Len                  L  30720
Poster Data                 30720 バイト
Quality                     L  1〜100（無圧縮では無視）
Type                        L  0 = 無圧縮、1〜3 = 圧縮
Poster Voice Size           L  上の表の値
Poster Voice Data
Time Scale                  L
ADPCM Rate                  L  0 / 2 / 4
Flame Number                L  ポスターを除くフレーム数
（画像 30720 バイト ＋ 音声）× Flame Number
```

数値はすべてビッグエンディアン（68000）。
画像は 128×120、1 ドット 1 ワード（GGGGGRRRRRBBBBBI）、1 ライン 256 バイト。

## 圧縮時（Type 1〜3）— SIV097C.X（0.97c）から解析

保存処理（`$6144`〜）の並び:

```
Poster Len (L) + 圧縮ポスター
Quality (L) / Type (L) / Poster Voice Size (L) + Poster Voice / Time Scale (L) / ADPCM Rate (L) / Flame Number (L)
（Flame Len (L) + 圧縮データ + 音声）× Flame Number      ← 詰め物なし。長さは奇数のこともある
```

圧縮ルーチン `$1983a` → `$19610`（保存はこちらを使う。`$17ff6` は色質 2・3 で色変換の引数を間違えている古い版）。
展開ルーチン `$18422` → `$17d70`。逆 DCT の表は起動時に `$10818` で作られる。

| 項目 | 内容 |
|---|---|
| MCU | 色質 1 = 8×8（Y Cb Cr）、2 = 16×8（Y Y Cb Cr）、3 = 16×16（Y Y Y Y Cb Cr）。左上から右へ、上から下へ。色質 3 の最下段は 8 ライン分だけ使う |
| 色変換 | 5bit の G R B を 16 倍して、Y = (R×0x2646 + G×0x4b23 + B×0xe98 + 0x4000) >> 16、Cb = (−R×0x158e − G×0x2a72 + B<<14 + 0x4000) >> 16、Cr = (R<<14 − G×0x3598 − B×0xa68 + 0x4000) >> 16。Y から 128 を引く（2 画素まとめて 32bit で引くので、下位の画素が 128 未満だと上位の画素からもう 1 引かれる） |
| 色差の間引き | 16 画素のうち 2,3,6,7,10,11,14,15 列目を取る。色質 3 は偶数行だけ。展開時は 1 サンプルを 2 画素（色質 3 は 2×2）に広げる |
| DCT | 整数の分離型。1 段目 (Σ cos×4096 + 0x800) >> 12、2 段目 (Σ + 0x4000) >> 15。0 番と 4 番の係数は掛け算せず、2 段目は 16bit で足して >> 3 |
| 量子化表 | JPEG 標準の輝度・色差表 × 10 ÷ 画質 を切り捨てて **符号を反転**（0 なら 1）。表は自然順（ジグザグ順ではない） |
| 量子化 | (係数 ± 表/2) ÷ 表、0 方向へ切り捨て。逆量子化は 係数 × 表 |
| 符号化 | JPEG ベースラインと同じ。標準の DC/AC ハフマン表（輝度・色差）、ジグザグ順、ZRL、最後の係数が 0 のときだけ EOB。DC の予測はフレームごとに 0 から。ビットは MSB から、0xFF のスタッフィングもマーカーも無い。最後は 8 ビット単位に切り上げ |

SiV の展開ルーチンの弱点（SiV 自身が圧縮したデータでも起きる）:

- 色差の AC 符号「ラン 1・サイズ 8」(0x18) を読み違える。以降のビットがずれ、係数を範囲外に書いてメモリを壊すことがある
- 逆 DCT の掛け算表が ±1023 までしかない。逆量子化後の係数がこれを超えると、その 8×8 が崩れる（画質 95 以上で目立つことがある）
- アドレスの上位 8 ビットにごみが入ったまま使う箇所がある（68000 の 24 ビットアドレスに頼っている）

このコンバータの圧縮（`Core/SivJpeg.cs`）は SiV と 1 バイト単位で同じ結果を出す（68000 エミュレータで SIV097C.X の圧縮ルーチンを直接動かして、色質 1〜3・画質 1〜100 の 45 通りで照合）。
ただし既定では上の 2 つの弱点に当たる係数だけを小さくして避ける（safe モード）。
展開は浮動小数点の逆 DCT なので、SiV の表引きとは 5bit の色で ±1〜2 ずれることがある。

## v16（mmvp.x 0.70d の拡張）— mmvp.x を逆アセンブルして確認

mmvp.x（nenetto 氏、1994）は SiV の VDT（無圧縮のみ）と、それを拡張した v16 を再生する。
マニュアルの謝辞によれば、VDT の仕様は pOno 氏の `SiV_vdt_Format.txt` を参考にしたもの。
アドレスは mmvp.x のテキスト先頭からのオフセット。

- 先頭は VDT と同じ `"SiV"`＋コメント＋$0A（`$1a7e`。"Si" と "V" だけを見る）。ヘッダの並びも VDT と同じ
- Type は 0（無圧縮）でなければ「Can't use compressed data!」（`$1502`）
- **ADPCM Rate の欄が $100 以上なら v16**（`$156a`〜）
  - `$1xx` = モノラル、`$2xx` = ステレオ（`$300` 以上はエラー）
  - 下位バイト 0 = 32kHz、1 = 44.1kHz、2 = 48kHz（それ以外はエラー）
  - 1 秒のバイト数 = 64000 / 88200 / 96000（ステレオは 2 倍）
- 1 フレームの音声バイト数 = 1 秒のバイト数 ÷ fps（整数除算。SiV のような偶数への切り上げはない）
- 音声は 16bit 符号付き・ビッグエンディアン。ステレオは L, R の順に交互。DMAC ch2 のアレイチェインで Mercury-Unit（$ECC080）へワード転送する（`$0b20`）。Mercury のコマンドは 32k=$9F / 44.1k=$AF / 48k=$BF、モノラルは bit1 を落とす（`$108e`）
- 制約（mmvp.x の計算が 16bit なので）: 1 フレーム（30720＋音声）が 65535 バイト以下、音声バイト数が偶数

### mmvp.x と SiV の違い（内蔵 ADPCM）

mmvp.x は 1 フレームの音声を `Rate × 1950 ÷ fps` で求め、偶数への切り上げをしない。
そのため **7.8kHz で 20 / 12 / 4 fps** の VDT（SiV では 196 / 326 / 976 バイト）は、mmvp.x では 195 / 325 / 975 バイトとして読まれる。
mmvp.x の 1 フレーム（30720＋音声）が奇数バイトになるので、2 フレーム目の画像が奇数番地に来て 68000 ではアドレスエラーになり、「Force exit!」で止まる（実際に 12fps・7.8kHz の SAILORMO.VDT で確認）。
音声を 1 バイト詰めたファイルを作っても、1 フレームが奇数バイトなのは変わらないので mmvp.x では再生できない。
15.6kHz と無音はどの fps でも一致する。
